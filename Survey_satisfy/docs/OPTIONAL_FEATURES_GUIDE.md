# 선택 기능 안내 (초보자용)

이 문서는 **필수가 아닌** 기능(연도 비교·AI 요약·Google PDF·부서 문항)을
「어디서 보는지 / 내가 뭘 해야 하는지」만 쉽게 정리한 것입니다.

핵심 설문·결과·보안은 이미 되어 있습니다. 아래는 **필요할 때만** 하시면 됩니다.

## 5. 연도 비교 — 어디서 보나요?

### 위치
1. 관리자 계정으로 로그인
2. `/admin` → **KPI** 탭
3. 응답이 **서로 다른 연도**에 2년 이상 쌓여 있으면  
   **「연도별 비교」** 그래프가 자동으로 나타납니다.

### 당신이 할 일
1. 설문 만들 때 **연도**를 올바르게 넣기 (예: 2025, 2026)
2. 각 연도 설문을 시작하고 응답을 받기
3. 관리자 KPI에서 그래프 확인

지금은 연도가 하나뿐이면 비교 그래프가 **안 나오는 것이 정상**입니다.

## 6. Google Drive · PDF — 당신이 할 일 (자세히)

기본 데이터는 **Supabase**에 저장됩니다.  
Google은 「Drive에 폴더 정리 + PDF 보고서」가 필요할 때만 켭니다.

### 준비물
- Google 계정 (진흥원 업무용 권장)
- 컴퓨터 브라우저
- 이 프로젝트 폴더의 `apps-script/Code.gs` 파일

### 단계 A — Apps Script에 코드 넣기

1. 브라우저에서 [https://script.google.com/](https://script.google.com/) 접속
2. **새 프로젝트** 만들기
3. 왼쪽 에디터에 있는 기본 코드를 **전부 지우고**
4. 로컬 파일 `Survey_satisfy/apps-script/Code.gs` 내용을 **전부 복사해서 붙여넣기**
5. 상단 프로젝트 이름을 예: `만족도조사_자동화` 로 저장 (Ctrl/Cmd + S)

### 단계 B — 웹 앱으로 배포

1. 오른쪽 위 **배포** → **새 배포**
2. 톱니바퀴(설정) → 유형 **웹 앱** 선택
3. 설정 예시:
   - 실행 계정: **나**
   - 액세스 권한: 처음엔 **나만** (나중에 조직으로 넓혀도 됨)
4. **배포** 클릭 → 권한 허용 창이 뜨면 Google 계정으로 허용
5. 나온 **웹 앱 URL**을 복사  
   (보통 `https://script.google.com/macros/s/..../exec` 형태)

### 단계 C — 프로젝트에 URL 넣기

1. `Survey_satisfy` 폴더에 `.env.local` 파일이 있는지 확인  
   없으면 `.env.example`을 복사해서 `.env.local`로 만듭니다.
2. 아래 줄을 채웁니다.

```env
NEXT_PUBLIC_GOOGLE_APPS_SCRIPT_URL=여기에_복사한_웹앱_URL
```

3. 개발 서버를 **완전히 끄고 다시** 실행합니다.

```bash
npm run dev
```

> 환경 변수는 서버를 다시 켜야 반영됩니다.

### 단계 D — 화면에서 테스트

1. 담당자로 로그인 → 설문 상세 열기
2. 아래쪽 **「작성중 수정 · 개선과제 · Google」** 버튼 클릭
3. **Drive·Sheet 생성 / 공식 PDF / 내부 PDF** 버튼으로 테스트

### 자주 막히는 곳
- URL을 넣었는데도 경고가 뜨면 → 서버 재시작 여부 확인
- Apps Script를 수정했다면 → **배포 관리 → 새 버전**으로 다시 배포해야 반영됨
- PDF가 비면 → Apps Script 실행 로그(실행 기록)에서 오류 확인

더 자세한 기술 배경은 `docs/SETUP.md`에도 있습니다.

## 7. Gemini 주관식 요약 — 당신이 할 일 (자세히)

### 위치
- 담당자: 설문 상세 → 결과 아래 **「주관식 의견 요약」**
- 관리자: `/admin` → KPI → 같은 패널

### 단계 A — API 키 발급

1. [Google AI Studio](https://aistudio.google.com/) 접속 (Google 계정)
2. **Get API key** / API 키 만들기
3. 키를 복사 (보통 `AIza...` 로 시작)

> 키가 유출되면 요금·악용 위험이 있으니 **채팅·카톡에 붙여넣지 마세요.**  
> `.env.local`과 배포 사이트의 비밀 환경변수에만 넣습니다.

### 단계 B — 로컬에 키 넣기

`.env.local`에 추가:

```env
GEMINI_API_KEY=발급받은_키
```

서버 재시작:

```bash
npm run dev
```

### 단계 C — 사용

1. 주관식 응답이 1건 이상 있어야 합니다.
2. **AI 요약 실행** 클릭
3. 요약·키워드·개선과제 초안이 나오면 **사람이 확인한 뒤** 보고서에 반영하세요.

키가 없으면 버튼은 보이지만 오류 메시지가 납니다. 정상입니다.

## 8. 부서 실제 문항 — 당신이 할 일 (자세히)

지금 앱에는 **공통 KPI + 7개 사업유형 기본/확장 문항**이 들어 있습니다.  
각 부서가 **예전에 실제로 쓰던 설문지**는 아직 반영되지 않았습니다.

### 왜 당신이 자료를 줘야 하나요?
문항 문구·척도·필수 여부는 부서마다 다르고, 파일도 PDF·한글·엑셀로 흩어져 있습니다.  
AI가 추측해서 넣으면 잘못된 문항이 공식 기준이 될 수 있어, **원본을 받는 것**이 안전합니다.

### 준비 방법 (초간단)
1. 부서별로 **최근 1~2년 설문지**를 모읍니다.  
   (PDF, 사진, 워드, 엑셀, 구글폼 링크 모두 OK)
2. 가능하면 `docs/QUESTION_INTAKE_TEMPLATE.md` 표를 채워 주세요.  
   (표가 어려우면 원본 파일만 주셔도 됩니다.)
3. 채팅이나 공유 폴더로 전달해 주세요.  
   예: 「콘텐츠지원본부 교육사업 2024 설문 PDF」

### 전달받은 뒤 제가 하는 일
- 유형별 문항 풀에 매핑
- 공통 KPI와 ID가 충돌하지 않게 정리
- 새로 만드는 설문부터 반영

## 배포(4번) — 나중에 요청하실 때

E2E(가입→설문→응답→결과)가 이상 없으면 말씀해 주세요.  
그때 제가 Vercel/Render 쪽 설정을 맞추고, 당신께는 대략 아래만 안내합니다.

1. 배포 사이트에 로그인
2. GitHub 저장소 연결
3. 환경변수 복사 (Supabase URL/키, `ADMIN_SETUP_SECRET` 등)
4. 배포 후 나온 URL을 `NEXT_PUBLIC_APP_URL`에 넣기

지금은 **테스트만** 하시면 됩니다.
